# Finder 状态与文件操作续审

日期：2026-10-05。范围：当前未提交工作区；继续只启用 WebDAV。三个审查点分别覆盖状态生命周期、复制移动、目录删除，主线程负责集成与回归。

## 云朵状态

- FileProviderItem 在构建时一次读取持久化元数据、实际缓存/暂存可用性和策略，生成不可变状态快照。单个 item 的不同属性不会各自读取不同时间的数据库状态。
- pendingUpload、pendingMove、pendingDelete 显示等待状态；只有正在上传的状态才设置 isUploading。上传失败和下载失败按是否有未同步本地修改区分。
- synced 不再单独证明本机有文件内容。下载完成必须有实际字节；最新版本还须匹配已观察到的远端 ETag，或是已接受的本地修改。
- remoteETag 保存目录列表观察到的版本；etag 保存本地字节对应的已确认版本。挂载和目录刷新不再把旧缓存自动升级成最新内容。
- 内容版本与状态版本分离：状态变化改变 metadataVersion，移动文件保留内容版本。所有版本摘要限制在 File Provider 的 128 字节上限以内。
- 创建文件先持久化不可变暂存、完整元数据和上传意图，再发布缓存和 Finder 条目。缓存发布失败保留暂存内容。

Apple 文档依据：[metadataVersion](https://developer.apple.com/documentation/fileprovider/nsfileprovideritemversion/metadataversion)、[isUploading](https://developer.apple.com/documentation/fileprovider/nsfileprovideritemprotocol/isuploading)。

## 复制与移动成本

- 已同步文件使用条件 WebDAV COPY；本地缓存通过 APFS 克隆复用。COPY 未返回可靠的目标版本时，只确认云端条目，不把本地副本标为已确认最新版本。
- Finder 创建模板的标识属于新文件，不能当成源文件标识。创建入口复用缓存写入时计算的 SHA-256，从索引中最多检查 32 个候选；只复用已同步、缓存物理属性一致、强 ETag 一致且没有待处理操作的源。
- 新输入仍需一次流式内容校验。索引未命中、不可读、源变脏或版本改变时回退为普通 create-if-absent 上传；挂载不扫描并计算全库内容哈希。
- 复制采用输入的不可变缓存快照。COPY 期间源文件变更，不会把新的本地字节绑定到旧的服务端复制结果。目标在请求期间出现新本地状态时保留该状态，返回前置条件失败。
- 缓存内容和索引发布使用每文件进程间锁；双文件克隆按固定顺序取锁。清理缓存在发布锁释放后执行，避免与提交锁形成锁顺序冲突。
- 尚未同步的文件复制使用不可变本地快照并排队，不复制旧云端内容。相同位置、相同名称的移动直接返回；普通移动使用服务端 MOVE 和缓存重命名，不下载并重新上传内容。

## 目录删除

- 普通 WebDAV 目录仅发送一次 collection DELETE，不枚举子项并逐文件删除。目录强 ETag 可用时使用；不拿子文件版本冒充目录版本。
- 这是用户授权的整目录删除，服务端处理目录内容。超时、5xx 或部分成功导致结果不确定时，不盲目自动重试，以免删除后来重新建立的目录。
- 加密目录采用 Cryptomator 父入口 unlink，不递归遍历分布式密文目录。被解除引用的子密文仍占用远端空间；本轮没有自动垃圾回收，避免误删仍被其他目录引用的数据。
- 清空回收站按整个回收条目删除。脏文件恢复备份及本地受保护缓存保留规则继续生效。
